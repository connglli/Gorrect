# Retained metadata observation design

Status: completed design record for the first retained metadata slice. The [implementation record](../implementations/completed-2026-10-31-retained-provider.md) holds validation and remaining limits; [observation](../../../docs/observation.md#binding-metadata) and [usage](../../../docs/usage.md#profiles) own the implemented contracts. The sections below preserve the proposed boundaries and enabling checks.

## First supported unit

Support controlled `roots-diagnostic` observation of generated, nonrecursive main-site, worker-cut and terminal captures using the explicit method roles below. Start with HotSpot JDK 17/21 conformance and the selected OpenJ9 JDK 21. Other OpenJ9 builds need their own conformance result; do not infer availability from the engine JDK. Keep natural mode, recursive/helper-frame reconstruction, virtual threads, custom loaders and unloading outside this first unit. Missing roots still produce incomplete coverage.

Propose one optional profile field, `bindingMetadata`, with `jvmti` as the unchanged default and `retained-class` as an explicit request. It has no CLI override and adds no GIR construct. The driver resolves it into a hashed internal observer plan and records the selected provider in the run bundle. Retained mode is not a fallback after failed native extraction. Malformed provider names are profile errors; known incompatible observation/provider combinations are unsupported. A requested provider whose launch or VM requirements cannot be established is unsupported before graph construction.

`retained-class` requests tagging, compilation/GC events as required, and class-load observation, but not local-variable access, bytecode access, redefinition or retransformation. Native `LOCAL_VARIABLES` remains clear. Keep the existing native provider and legacy artifact reader intact. The goal is avoiding OpenJ9's known local-access/VarHandle restriction, not proving unchanged compiler policy or transparent observation.

## Controlled launch

A load hook observes bytes at its position in a transformation chain; it cannot alone certify the final definition. [JVMTI class loading and preparation](https://docs.oracle.com/en/java/javase/21/docs/specs/jvmti.html#ClassFileLoadHook) and the prior investigation justify the following restricted launch, not an unrestricted anti-transformation guarantee.

The driver must use the canonical target executable under the queried installation, rather than an arbitrary wrapper, and retain executable/library/release identities. It owns the complete classpath, main class, observer and option list. Reject other agents, JDWP, custom system loaders, patch/module/boot loading changes and indirect option files. Clear inherited Java option/classpath and native injection variables; reject profile reintroduction. Retain the resolved environment. Initially admit only a driver-reviewed VM-argument allowlist; unknown launch sources are unsupported instead of silently called controlled.

Disable attachment using the driver-owned [HotSpot disable-attach option](https://docs.oracle.com/en/java/javase/21/docs/specs/man/java.html) or [OpenJ9 attach property](https://eclipse.dev/openj9/docs/attachapi/), and check the effective selected-VM setting. OpenJ9 also disables shared-cache/AOT reuse for this provider. These are recorded diagnostic policy changes. Only reviewed project support/client content is admitted; a digest of an arbitrary compatible jar does not establish trust. Those bytes are hashed and checked for generated-class shadowing and agent manifests; this is a declared harness trust boundary, not protection against hostile native code in the process. An observer cannot discover every other JVMTI environment or invisible retransformation.

## Exact loaded-code certificate

Use a bounded, non-transforming startup `ClassFileLoadHook` and `ClassPrepare` listener before Case can load. Copy the actual Case input bytes into native storage; writing/hashing can occur outside the hook. Record one expected definition attempt. Duplicate same-name attempts, unnamed/unpaired definitions, capacity failure or any later modification event prevent certification. Do not request retransformation merely to move later in the chain. The controlled-launch restriction supplies the missing final-transform condition.

Pair the load's defining loader with the prepared class using JNI identity comparison, then enumerate method tokens, names and descriptors and verify each declaring class. Loader and class mirrors use weak JNI references; a cleared weak reference is failure, never the bootstrap-loader identity. Distinguish bootstrap explicitly. The first unit requires the intended Case to use the normal system defining loader and rejects duplicate definitions even if their signatures match.

Add `TargetSession.open(args, Case.class)` for newly emitted programs. After the bundled native library is loaded, bind that exact mirror to the prepared certificate and publish startup evidence before properties/HELLO. The host validates copied bytes and identity evidence before acknowledging startup; graph initialization remains blocked until that acknowledgement. Preserve `open(args)` for old native-provider classes; it cannot silently satisfy a retained request. Current main startup already precedes initialize, so no workload object is passed into certification. Release temporary comparison/method-query JNI locals before heap walking; retain no strong class, loader or workload registry.

The host compares the copied hook bytes byte-for-byte with the exact retained `Case.class`, identifies both by SHA-256, and parses that same immutable byte array through RetainedLocalMetadata. A matching filename, signature, emitted Java, method bytecodes alone, or retained-file digest is insufficient. Successful preparation supplies the JVM-accepted-definition precondition; malformed/failed loads acquire no successful certificate. Method tokens remain opaque within one run and are rechecked against the live certified mirror when consumed.

## Capture-consistent frame evidence

Compiler scopes supply names and slot intervals; actual roots supply values. The [JVMTI stack-frame interface](https://docs.oracle.com/en/java/javase/21/docs/specs/jvmti.html#GetStackTrace) provides method/location samples, not a continuous-lifetime certificate. Retained mode brackets the existing FollowReferences call with bounded standard stack traces for the exact participating threads. Require JVM bytecode-index location format before interpreting any location. The runtime already owns live caller/worker Thread objects; a new internal capture overload may pass those control objects, with IDs checked independently, without passing workload values. Their references expire with the cut.

Select each participant's method role from independently validated GIR/control/cut identity, never by searching for any convenient generated frame:

| Capture context | Expected method | Binding obligations |
| --- | --- | --- |
| Ordinary main checkpoint | `Case.execute` | Live source declarations selected by the observation contract. |
| Suspended caller at a worker cut | `Case.execute` | The caller's declarations for that group/cut. |
| Worker at a coordinated cut | Its declared `Case.workerN` method | That worker's declarations and group-round activation. |
| Mandatory final visit `(operation=0, occurrence=1)`, without a worker cut | `Case.main(String[])` | Empty GIR binding set after `execute` returns and the outer scope ends. |

Preserve a before/after frame pair for every participant, including empty ones. Require one occurrence of the role's exact certified method/name/descriptor, the same thread/method/depth and valid equal BCI on both sides. The terminal caller remains worker 0/activation 1; it needs its `main` frame even though `.gbind` is empty, cannot carry execute-local declarations, and cannot substitute a departed execute frame. Unknown roles, missing expected frames or ambiguous activations remain incomplete.

Capture stays inside the role's checkpoint/parallel invocation until acknowledgement or worker-cut release. Main and execute each run once; workers use fresh threads and known group rounds. This parked, nonrecursive call supplies the stability argument; endpoint equality alone does not rule out leave/re-enter behavior. No suspended-thread/local-read capability is needed. No stack, native allocation or JNI work occurs inside heap callbacks.

A raw stack root must match that participant's actual thread, method token, depth and JVM local-slot coordinate. Preserve raw snapshot bytes, including a missing location. Use a nonnegative raw BCI only when it agrees with the bracketed frame. A raw missing BCI may use the independently certified frame BCI; missing method/depth/slot/root cannot be repaired. Match the actual slot and BCI to one compatible retained LVT interval and emitted variable/descriptor. Reject overlapping matches, invalid slots/locations, missing tables, truncated/disagreeing frame pairs and ambiguous activations. Extra roots are not assigned by their expected targets. A present binding still needs a unique compatible physical root; null still needs primitive presence without contradictory evidence.

The supplied-VM depth/slot convention and this parked-call argument must pass actual generated two-worker and caller cases before that VM adapter enables recovery. If the VM omits origins or exposes a coordinate space that cannot be matched, report incomplete coverage. Do not synthesize omitted/inlined frames. Existing compilation witnesses stay separate; even a successful certificate and frame pair cannot prove that an activation stayed compiled. HotSpot heap-walk escape barriers and OpenJ9 stack-inspection effects remain declared.

## Evidence and classification

Keep `.gsnap`, `.gbind` and `.gcut` unchanged. Add bounded version 1 `CodeEvidence` once per run and `FrameEvidence` per retained capture, with magic/version, run/capture identity, explicit status/counts and EOF framing. Code evidence refers to the copied class bytes and records observer-owned class/loader tokens, intended-class binding, method mappings and modification/failure state. These tokens are distinct from heap tags and object addresses. Its startup certificate is immutable in meaning; a final completion/invalidation status is required for a pass. Frame evidence records ordered participants, their validated capture roles, before/after frames and the certificate epoch/status (a monotonic definition-generation counter) bracketing the walk. A changed epoch or missing final status cannot certify the run, while independently valid earlier refutations remain visible. Suggested ceilings are the reader's 16 MiB class limit, 256 Case methods, 17 participants and 64 frames per participant; request an extra frame to detect truncation. These are implementation limits, not JVM laws.

The hashed observer plan and layout explicitly select `jvmti` or `retained-class`; absence means the defined legacy native rule. Unknown/conflicting selections are extraction errors. A retained capture requires its code/frame evidence; missing files cannot fall back to VM tables or an empty participant set. Offline verification needs only bundled bytes/evidence, not the target installation. Replay preserves the provider and controlled launch, obtains fresh certificates and frame samples, and never reuses old method/class/loader tokens.

Preflight distinguishes configured facility availability from per-capture evidence. Report the selected metadata source and native capability bits separately. `local-bindings` availability can use either a valid native table facility or the complete configured retained mechanism; exercise/verification still require the current declarations and raw physical origins. No report bit is proof of itself. Startup unsupported configuration/certification failure stops before graph initialization. Missing/malformed/inconsistent retained evidence is extraction failure or incomplete coverage; it cannot become invalid GIR, guessed null or a graph pass. Preserve independently covered named-root/scalar refutations beside those gaps using current partial projection. Control crashes, native allocation failure and timeouts keep their existing categories and artifacts.

## Integration and enabling checks

Deliver one complete retained-provider unit across driver/profile resolution, generated startup, native certificate/frame capture, shared bounded codecs, verifier/provider projection and capability reporting. Keep metadata lookup as a small explicit provider boundary; do not add a general plugin framework or replace the graph/oracle. Usage/observation documents own the accepted provider contract; working notes retain the investigation and qualifications.

Before support is enabled, test actual emitted Case classes on JDK 17/21 HotSpot and selected OpenJ9: exact hook bytes and intended mirrors, method declaring classes, caller plus two workers across repeated cuts, ordinary `execute` followed by mandatory terminal `main` capture, empty-program/final-only and empty/null binding participants, slot reuse and real raw roots without local access. Reject wrong terminal roles, spurious execute-local declarations and attempts to omit final certification; preserve the existing outer-scope lifetime boundary. Include wrong bytes/LVT-only changes, wrong/duplicate loaders, missing prepare/bind, modification events, cleared weak mirrors, unknown metadata rules, damaged envelopes, wrong thread/depth/method/slot/BCI, truncation and before/after disagreement. Retain the earlier downstream-transform and invisible-retransform negative controls to demonstrate why uncontrolled launches are unsupported. Test cause-preserving startup failure, deadlines, no fallback, old native bundles, offline verification and fresh replay.

A VarHandle worker must establish compilation with local access absent, and its actual frame/GC requirements must be checked independently. Missing optimized origins or deoptimization can leave coverage unmet even when metadata succeeds. The prior investigation's 22 outcomes establish building blocks only; no new VM run or production result is claimed by this proposal. Provider spelling, the retained plan/envelope schemas and VM-adapter coordinate conformance require agreement and implementation checks before shipping.
