# Natural history liveness proposal

Status: unaccepted proposal for the remaining [stage 13](../implementations/2026-10-30-stage13.md) work. No production behavior or unsupported guard changes here. Recommend actual-path conditional capture first, then a restricted sequential reference-history subset whose locals cannot change reachability. The investigation establishes no general natural reference-history policy.

## Contract and existing boundary

Natural observation omits lifetime fences. Source-level future uses select graph obligations at a capture; they do not certify strong reachability throughout a preceding GC interval. The [Java 17 reachability rules](https://docs.oracle.com/javase/specs/jls/se17/html/jls-12.html#jls-12.6.1) permit stack references to become unnecessary when field values are cached. [Reference.reachabilityFence](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/ref/Reference.html#reachabilityFence(java.lang.Object)) supplies an explicit lifetime guarantee; adding it changes this profile's contract. Presence recording, metadata requests, heap walking and possible materialization remain declared observer effects.

A later non-null capture or an earlier successful acquisition certifies no continuous protection interval. Every required non-null binding still needs actual method/thread/frame/slot/BCI evidence and one compatible observed target; null needs explicit presence without a contradictory root. Missing or ambiguous roots are incomplete coverage, not proof of collection. Compiled installation, source scope, metadata alone, primitive identities and a later materialized frame cannot repair that gap.

[Current analysis](../../../engine/src/main/java/io/connglli/gorrect/engine/observe/NaturalLiveness.java) expands unconditional literal control flow and distinguishes loop definitions while indexing checkpoints by statically counted site visits. Optional earlier visits invalidate that positional correspondence. More importantly, `HistoryOracle` and `ConcurrentHistory` give every lexical handle to `ReferenceFrontier.expand`, which treats it as a strong root. Filtering checkpoint handles alone cannot make those clearing constraints valid for natural execution.

## Conditional main-thread captures

Begin with `if-present` in the existing exact strong-graph profile, preserving unsupported reference/contended histories and worker cuts. Keep input/type validation over every syntactic branch, including unreachable bodies. Derive the actual main path independently from the exact oracle, then require scalar/control markers to match before using that path to narrow local obligations. Scalar branches from stage 14 can reuse the mechanism only after their execution contracts are complete.

Separate capture candidates from required bindings. The emitter can record primitive nullness for every live lexical reference binding at the executed site without emitting predicted targets, branch values, or future heap contents. The complete candidate declaration set is checked against source scope; only independently validated future uses before that particular activation ends select required physical roots. An unused candidate is neither an inferred null nor a mandatory root. This needs explicit two-set handling in emission, declaration coverage and projection; merely accepting extra declarations in the current one-set contract would weaken validation.

Reconstruct bounded loop/scope activations and actual visits from validated execution, then walk the resulting main path backward. A fresh loop definition kills the preceding definition's uses; release/scope exit ends its obligation. Do not index this path using `HistoryPlan`'s maximum visits, or infer a route from the presence/absence of snapshot files. Repeated optional captures can have the same site and actual visit number as a different expanded iteration. Candidate evidence can keep version 1 `BindingEvidence`; old unconditional bundles retain their existing expected declaration sets, with the candidate-selection rule explicit in retained emission metadata and bound to the source/layout provenance. Reject unknown or inconsistent selection modes; never guess from file length.

For histories, validate reference/control choices without local capture pruning before deriving future-use obligations, then match captures against the surviving history frontier. Both passes share the checking budget; a path that fails capture consistency cannot establish a pass. An incomplete suffix cannot establish that a binding has no future use. Such captures require a sound conservative continuation analysis or remain incomplete for local obligations. Independent named-root/scalar refutations must remain visible beside that gap. Do not let an unvalidated branch or missing later file remove an earlier required comparison. Bound path expansion, retained activation/use sets and snapshot cells under the existing checking limits.

## Restricted sequential reference histories

A useful first reference subset avoids uncertain local-only protection. At every possible modeled processing boundary, require every live non-null handle target to be strongly reachable from named roots through strong heap edges. Keep the first slice sequential, with ordinary object referents and the existing opaque slot-wrapper/implicit-queue abstraction. New wrapper-as-referent graphs, native roots, cleanup actors, finalization and resurrection require their owning contracts first. The [static/heap reachability rules](https://docs.oracle.com/javase/specs/jls/se17/html/jls-12.html#jls-12.6.2) supply the mandatory-root basis under the existing reachable root-holder and ordered-store contract.

Let `R` be the named roots, `H` the live handle targets, and `S` the strong closure of `R`. Require `H` to be a subset of `S`. For every retained clearing state, following strong, strong-plus-soft, or strong-plus-soft-plus-weak edges from `R` gives the same reachable set as starting from `R` plus any subset of `H`. All of those traversals already include `S`. Their clearing eligibility and atomic clearing groups therefore have identical inputs regardless of optimizer-local retention. This is a sufficient graph condition; it certifies no physical local root.

Prove the condition over every legal reference-choice path before launch and repeat it during offline checking. Reuse the existing bounded exploration and accounting rather than a new scheduler. Check it before each frontier expansion, including scope/acquisition exit and terminal cleanup, and for successor states before uncertain locals can constrain choices. A proof that first uses unjustified local protection to prune branches is circular. `HistoryPlan` placeholder graphs cannot establish the condition. Existing `Graph.required()` rejects non-strong slots and `accessible()` follows them; neither directly computes the named-root strong closure needed here.

A simple induction supports reuse of current clearing rules: the initial program state has no GIR handles; at every admitted state adding/removing local roots changes no strength closure, and every next reference choice is therefore enumerated without uncertain protection. Invariant failure is an unsupported natural combination, not invalid GIR; exhausted proof work is a checking limit. A successful recorded path cannot excuse a failing alternate branch. Ordinary invalid preconditions and transactional rejection keep their existing classifications.

The enabling proof also needs a generated-operation audit: temporary ordinary references and intermediate strong stores must not create an uncovered mandatory protection interval between modeled boundaries. Initialization's temporary construction roots must end before modeled clearing starts. A new allocation bound before publication, a non-null acquisition outside the named strong closure, or removal of the last named path while its handle remains live is outside this first subset. Legitimate tests can start with rooted owners and unprotected initial referents, install wrappers while values remain named-rooted, release aliases, and then unlink the named strong path. Arbitrary collection and delivery delay remains permitted; no clearing or reclamation is required.

Keep physical local capture independent of that proof. A required natural local with no usable origin makes capture incomplete even when its target has a valid named root. Conversely, an impossible clearing of a referent protected by a certified named strong path remains a refutation beside unrelated missing local evidence. Do not silently drop all local coverage to obtain a pass. Keep full lexical values in interpreter state for later operations; apply the actual-path future-use filter only to checkpoint comparison obligations. `ReferenceFrontier.match` currently compares lexical handles too, so its observation input must change together with projection. GC protection and captured-binding selection are separate interfaces.

## Arrays and later composition

Unused array shape declarations are already permitted and regression-tested. Current capability checks reject initial array objects and any syntactic array allocation; array identity binding crosses JNI and is diagnostic. A separate small refinement could exclude allocations under literal zero-trip repeats after normal validation of those bodies. It must prove that no initial construction or reachable instruction executes diagnostic array binding. Initial unrooted arrays, allocations on any admitted branch, and unsupported identity reads stay guarded. General dead-branch proofs must cover every legal path, not only the saved trace.

Worker natural capture needs its own future-use and protection proof over every worker and suspended caller; reuse the coordinated cut/participant contract rather than another rendezvous. A cut certifies one paused view, not a preceding interval. Calls/unwind additionally need stage 14's activation identities, normal/exceptional successor paths and pending return roots. Stage 15's first-class wrappers require queue/pending ownership and wrapper reachability before extending the root argument; primitive WrapperId records are not roots. Stronger controls such as fences or deliberate native leases belong to an explicitly controlled profile.

## Independent checks and enabling tests

The ignored `natural-history` self-check uses a separate bitset closure model. It enumerates all 1,000 three-node directed graphs with at most one outgoing edge per node, three edge strengths, all named-root/clearing masks and redundant local subsets, plus arbitrary additional seeds. All 5,898,240 closure equalities pass across 64,000 root/clearing states. A separate 256-case optional-visit model finds 110 cases where maximum-expansion positions misassign actual-visit future-use bits. These are mathematical checks of the closure lemma and indexing counterexample, not a JVM liveness or full reference-history proof. No target execution or compiled-frame claim is made.

| Case | Required enabling result |
| --- | --- |
| Cached payload or folded alias test after GC | Future syntax cannot forbid clearing through a local-only root; retain the general-history guard. |
| Taken/skipped conditional captures, nested repeats and fresh loop definitions | Source/control identities select the actual activation; skipped earlier visits cannot change another capture's obligations. |
| Missing suffix, presence entry, local origin or later capture | Preserve incomplete coverage and any earlier independent graph/scalar violation. |
| Named-root redundancy versus allocation/acquisition/unlink counterexamples | Independent small histories agree; every unsafe alternate path is unsupported before execution. |
| Explicit clear while target remains named-rooted | Clear follows its own operation contract, without being mistaken for forbidden GC clearing or mandatory queue delivery. |
| Bare array declaration, zero-trip allocation and live allocation | Preserve current declaration support; only a proved unreachable binding call may bypass the allocation guard. |
| Worker/call/first-class-wrapper combinations | Retain their separate gates until the composed protection, activation and evidence contracts are proved. |

## Implementation order

1. Add complete candidate-presence versus required-root handling and actual-path analysis for exact conditional main captures, with old-bundle compatibility and independent branch/loop models.
2. If useful, narrow the array-allocation check for structurally zero-trip bodies; this can be reviewed independently of reference semantics.
3. Add the bounded named-root coverage proof and generated-operation audit, then enable only the sequential reference subset and its full trace/capture checks.
4. Keep general local-only reference histories unsupported until an independent lifetime/processing certificate or a sound separately specified semantics exists. Do not replace uncertain reachability with unrestricted clearing choices and call the result complete validation.

Agreement is needed on the retained metadata identifying the candidate rule and the restricted subset before implementation. Compiler-dependent liveness inference, native root leases, and a universal natural reference profile remain unresolved.
